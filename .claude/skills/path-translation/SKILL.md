# Path Translation Middleware

Installs a `PreToolUse` middleware that transparently rewrites virtual paths to
physical, tenant-specific paths inside the container. The agent always sees the
virtual namespace; the filesystem always sees the physical namespace. No agent-side
changes are needed.

## How it works

```
Agent writes:  /mnt/user-data/notes.md
  ↓ (translate-paths.ts middleware)
Filesystem:    /workspace/agent/tenants/uid-123/tid-456/notes.md
```

The middleware runs as a NanoClaw `PreToolUse` slot (see `middleware-chain.ts`).
It reads the full hook input from stdin, rewrites any string fields inside
`tool_input` that start with `NANOCLAW_VIRTUAL_PREFIX`, then emits
`hookSpecificOutput.updatedInput` so the SDK swaps in the translated input before
executing the tool. Subsequent middleware slots receive the translated paths.

## Installation

1. Copy the middleware script into your group's hooks directory:

   ```bash
   GROUP=<your-group-folder>   # e.g. groups/my-agent
   mkdir -p "${GROUP}/hooks"
   cp "${CLAUDE_SKILL_DIR}/scripts/translate-paths.ts" "${GROUP}/hooks/"
   ```

2. Add the `PreToolUse` middleware slot to the group's `container.json`.
   The file is generated by the host at container spawn time from
   `src/group-init.ts`. Edit it directly if it already exists under your
   group folder, or adjust `src/group-init.ts` to include the slot.

   ```json
   {
     "middlewareChain": {
       "PreToolUse": [
         {
           "name": "path_translation",
           "command": "NANOCLAW_VIRTUAL_PREFIX=/mnt/user-data NANOCLAW_PHYSICAL_BASE=/workspace/agent/tenants/uid-$(cat /workspace/tenant-uid)/tid-$(cat /workspace/tenant-tid) bun /workspace/agent/hooks/translate-paths.ts"
         }
       ]
     }
   }
   ```

   Adjust the `NANOCLAW_PHYSICAL_BASE` expression to match your tenant-ID
   injection strategy (env var, file, or hardcoded).

## Configuration

| Variable | Default | Purpose |
|---|---|---|
| `NANOCLAW_VIRTUAL_PREFIX` | `/mnt/user-data` | Virtual path prefix the agent addresses |
| `NANOCLAW_PHYSICAL_BASE` | `/workspace/agent` | Physical base directory on the container FS |

## Security

- Only paths that start with `NANOCLAW_VIRTUAL_PREFIX` are translated.
  All other paths pass through unchanged so normal workspace access works.
- The script blocks directory traversal (`..` segments) in the virtual path
  to prevent escaping the tenant boundary.
- If the script crashes or times out, the middleware chain fails open
  (the tool call proceeds with the original paths). This matches the
  fail-open contract of the middleware chain documented in `middleware-chain.ts`.

## Composing with other middleware

Because `updatedInput` is threaded through successive slots, you can place
`path_translation` first in the `PreToolUse` chain and then layer sandbox or
loop-detection middleware after it — the later slots will see the already-
translated physical paths.
